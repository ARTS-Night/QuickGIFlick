# Phase 4 measured results — 2026-08-28

All capture runs used the interactive Windows desktop exposed by Windows MCP:
one 1366 x 768 primary display, release build, 15 FPS target. Cursor moves
provided a small-motion stimulus. Values below are measured output, not
estimates.

## ScreenDelta update transport

`poll_updates`, 8 seconds:

| Full | Delta | Delta payload | Unchanged | DXGI frames acquired | Readback time |
| ---: | ---: | ---: | ---: | ---: | ---: |
| 5 | 11 | 1,186,696 B | 105 | 16 | 9.2296 ms cumulative |

This confirms all three public update forms on the target Windows session. The
first update was Full; small pointer-related damage used Delta; idle polling was
Unchanged.

## Recording-store forced spill

With `QUICKGIFFLICK_RECORDING_MEMORY_MB=1`, an 8-second recording completed
normally with 850,944 B resident payload and 12,589,056 B spill payload. The
resulting GIF decoded as 14 frames and 8.00 seconds. No matching temporary
recording file remained after process exit.

The earlier baseline and Phase 4 run did not use a controlled identical visual
workload, so this table is evidence of bounded payload behavior, not a claim of
comparable CPU or encode-speed improvement. The raw-payload and working-set
figures are recorded exactly as observed.

## 60-second recording

The 60-second run finished normally. At 30 seconds its process working set was
46,456,832 B and private memory was 35,282,944 B. At Stop, resident payload was
33,459,436 B (within the 33,554,432 B default limit) and spill payload was
8,490,516 B. ScreenDelta reported 8 Full, 73 Delta, and 821 Unchanged updates;
the saved 17,200,927-byte GIF decoded as 81 frames and exactly 60.00 seconds.

## Limits retained deliberately

- These tests do not establish a CPU utilization or encode-latency comparison;
  that requires a repeatable controlled motion workload.
- DXGI move rects and cursor shape composition are not yet represented as
  Delta updates, so empty or uncertain damage stays on the Full fallback.
- GIF output is currently full canvas per visual update; partial GIF frames
  need separate compatibility testing before adoption.
